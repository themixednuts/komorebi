# TypeScript/QuickJS and Lua/LuaJIT plugin DX

This document compares the authoring experience for three realistic komorebi automations. Each pair implements the same behavior, but uses the natural conventions of its language. The examples are intentionally not presented as programs that the current spike can execute unchanged.

## What exists, what is planned, and what is missing

The maturity label matters more than the syntax:

| Label | Meaning | APIs used below |
|---|---|---|
| **Proven** | Executed by the QuickJS spike and covered by its tests | TypeScript stripping with Oxc, relative ESM imports, top-level `await`, source maps, `komorebi:host.focus(direction)`, a Tokio-backed promise, resource limits, preemptive script cancellation, and whole-runtime reload with JSON-like state handoff |
| **Planned** | Grounded in the implementation call stacks and action catalog, but not wired to either script runtime | Binding a stable action ID and named arguments against the current catalog, then asynchronously invoking the resulting command; authenticated extension-host transport; bounded extension event subscriptions |
| **Proposed** | Required to make these examples safe and pleasant, but absent from the current spike and implementation plan | Typed event payloads, plugin lifecycle callbacks, exact-window routing, configuration snapshot reads, structured logging, and a host-call `AbortSignal`/cancellation token |

The spike's only generated declaration today is:

```ts
declare module "komorebi:host" {
  export type Direction = "left" | "right";
  export function focus(direction: Direction): Promise<void>;
}
```

Everything else imported from a `komorebi:*` module below is a **proposed production API sketch**. The existing implementation design supports the action invocation path, but it does not yet generate TypeScript declarations or Lua annotations for it.

The proposed boundary is deliberately small:

```text
plugin callback
  -> generated, typed capability
    -> bind stable action ID + named inputs against current catalog
      -> authenticated async command queue
        -> manager validates and applies the action
```

Scripts do not construct protocol messages, open named pipes, or run shell commands. A stale or unavailable catalog action fails at the binding boundary.

## Proposed lifecycle and host surface

The examples assume the host generates TypeScript declarations and LuaLS annotations from the same action/event schema. These abbreviated declarations explain the calls without claiming they exist today.

```ts
// Generated by komorebi; not user-authored.
declare module "komorebi:plugin" {
  /** ASCII-lowercase executable basename, normalized once by the host. */
  export type ProcessName = Lowercase<`${string}.exe`>;
  export interface WindowRef { readonly id: string }
  export interface WindowInfo {
    readonly window: WindowRef;
    readonly processName: ProcessName;
    readonly title: string;
  }
  export type Event =
    | { readonly type: "window-managed"; readonly window: WindowInfo }
    | { readonly type: "focus-changed"; readonly window: WindowInfo | null };
  export interface Context {
    readonly signal: AbortSignal;
    /** Separate, bounded signal for rollback after `signal` is cancelled. */
    readonly cleanupSignal: AbortSignal;
    log(level: "info" | "warn" | "error", message: string,
        fields?: Readonly<Record<string, unknown>>): void;
  }
  export interface DisposeContext extends Context {
    readonly reason: "disabled" | "uninstalled" | "reload-transferred";
  }
  export interface Plugin<State> {
    onEvent(event: Event, context: Context): Promise<void>;
    snapshot(): State;
    restore(state: State): void;
    dispose(context: DisposeContext): Promise<void>;
  }
}

declare module "komorebi:actions" {
  export class ActionError extends Error {
    readonly code: "unavailable" | "invalid-input" | "stale-catalog" | "rejected";
  }
  export interface InputsByAction {
    readonly "set-named-workspace-layout": {
      readonly name: string;
      readonly layout: "bsp" | "columns" | "rows" | "vertical-stack"
        | "horizontal-stack" | "ultrawide-vertical-stack" | "grid"
        | "right-main-vertical-stack" | "scrolling";
    };
    readonly "set-animation-enabled": { readonly enabled: boolean };
    readonly "set-border-enabled": { readonly enabled: boolean };
    readonly "set-transparency-enabled": { readonly enabled: boolean };
    readonly "set-border-colour": {
      readonly "window-kind": "single" | "unfocused" | "unfocused-locked";
      readonly red: number;
      readonly green: number;
      readonly blue: number;
    };
  }
  export function invoke<Id extends keyof InputsByAction>(
    id: Id,
    namedInputs: InputsByAction[Id],
    options: { readonly signal: AbortSignal },
  ): Promise<void>;
}

declare module "komorebi:windows" {
  import type { WindowRef } from "komorebi:plugin";
  export function routeManagedWindow(
    window: WindowRef,
    workspace: string,
    options: { readonly signal: AbortSignal },
  ): Promise<void>;
}

declare module "komorebi:configuration" {
  export interface AppearanceSnapshot {
    readonly animationsEnabled: boolean;
    readonly bordersEnabled: boolean;
    readonly transparencyEnabled: boolean;
    readonly singleBorderRgb: readonly [number, number, number];
  }
  export function readAppearance(
    options: { readonly signal: AbortSignal },
  ): Promise<AppearanceSnapshot>;
}
```

`routeManagedWindow` is not a convenience wrapper around `send-container-to-named-workspace`. The catalog action targets the focused container, so using it in a window-managed event handler would race with focus changes. Production needs an atomic manager-owned action keyed by the event's validated `WindowRef`.

The Lua examples use an equivalent proposed surface. `actions.invoke` and other brokered functions are yielding calls that return `nil, error` rather than promises. The host resumes the coroutine on its Tokio task. `context:cleanup()` returns a separate, bounded context for rollback after the event context is cancelled.

## 1. Route real applications and select workspace layouts

Behavior:

- Route Teams and Zoom to `meetings` with a grid layout.
- Route VS Code and Visual Studio to `code` with a BSP layout.
- Route Steam and the configured games to `games` with a rows layout.
- Match the exact managed window rather than whichever window happens to be focused.
- Treat cancellation as normal during reload and report other broker failures.

### TypeScript/QuickJS

```ts
// routing/config.ts — user-authored, no tsconfig.json required
import type { ProcessName } from "komorebi:plugin";

export type Layout = "bsp" | "grid" | "rows";
export interface Route {
  readonly workspace: string;
  readonly layout: Layout;
}

export const routes = new Map<ProcessName, Route>([
  ["ms-teams.exe", { workspace: "meetings", layout: "grid" }],
  ["zoom.exe", { workspace: "meetings", layout: "grid" }],
  ["code.exe", { workspace: "code", layout: "bsp" }],
  ["devenv.exe", { workspace: "code", layout: "bsp" }],
  ["steam.exe", { workspace: "games", layout: "rows" }],
  ["eldenring.exe", { workspace: "games", layout: "rows" }],
]);
```

```ts
// routing/plugin.ts
import { ActionError, invoke } from "komorebi:actions";
import type { Event, Plugin } from "komorebi:plugin";
import { routeManagedWindow } from "komorebi:windows";
import { routes } from "./config.ts";

interface RoutingState { readonly routed: number }
let state: RoutingState = { routed: 0 };

const plugin = {
  async onEvent(event, context) {
    if (event.type !== "window-managed") return;
    const route = routes.get(event.window.processName);
    if (!route) return;

    try {
      await invoke("set-named-workspace-layout", {
        name: route.workspace,
        layout: route.layout,
      }, { signal: context.signal }); // PLANNED: real stable action ID/inputs.
      await routeManagedWindow(event.window.window, route.workspace, {
        signal: context.signal,
      }); // PROPOSED: exact-window action is missing today.
      state = { routed: state.routed + 1 };
    } catch (error) {
      if (context.signal.aborted) return;
      const code = error instanceof ActionError ? error.code : "unexpected";
      context.log("error", "could not route managed window", {
        code,
        processName: event.window.processName,
        workspace: route.workspace,
      });
    }
  },
  snapshot: () => state,
  restore: restored => { state = restored; },
  async dispose() {},
} satisfies Plugin<RoutingState>;

export default plugin;
```

The relative import, `.ts` loading, type stripping, and async execution model are proven. Events, lifecycle, catalog invocation, structured logging, and exact-window routing are not.

```lua
-- routing/plugin.lua
local actions = require("komorebi.actions")
local windows = require("komorebi.windows")
local routes = require("routing.config")

local plugin = { state = { routed = 0 } }

function plugin:on_event(event, context)
  if event.type ~= "window-managed" then return end
  local route = routes[event.window.process_name]
  if route == nil then return end

  local ok, err = actions.invoke("set-named-workspace-layout", {
    name = route.workspace,
    layout = route.layout,
  }, context) -- PLANNED: real stable action ID/inputs.
  if not ok then
    if context:cancelled() then return end
    context:log("error", "could not set workspace layout", {
      code = err.code or "unexpected",
      workspace = route.workspace,
    })
    return
  end

  ok, err = windows.route_managed_window(
    event.window.window, route.workspace, context
  ) -- PROPOSED: exact-window action is missing today.
  if not ok then
    if context:cancelled() then return end
    context:log("error", "could not route managed window", {
      code = err.code or "unexpected",
      process_name = event.window.process_name,
      workspace = route.workspace,
    })
    return
  end
  self.state.routed = self.state.routed + 1
end

function plugin:snapshot()
  return { routed = self.state.routed }
end

function plugin:restore(restored)
  self.state = restored
end

function plugin:dispose(_context) end

return plugin
```

`require("routing.config")` is idiomatic Lua, but a production loader still needs a confined plugin-local resolver. The benchmark proves a host-populated `package.preload`; it does not prove safe filesystem-backed `require` resolution.

## 2. Focus-aware meeting and gaming modes

Behavior:

- Enter meeting mode when Teams or Zoom receives focus: keep animations, borders, and transparency enabled.
- Enter gaming mode when a configured game receives focus: disable animations, borders, and transparency.
- Restore the exact previous appearance when focus leaves a special app.
- Carry mode and original appearance across hot reload as plain data.
- Roll back a partially applied transition when a broker call fails.
- On disable/uninstall, clean up active changes. A reload transfers state first, so disposal of the old runtime must not undo the new runtime's ownership.

This needs a configuration read capability that is not in the current plan. Without it, cleanup would hard-code guessed defaults and overwrite user settings.

### TypeScript/QuickJS

```ts
// modes/plugin.ts
import { invoke } from "komorebi:actions";
import { readAppearance, type AppearanceSnapshot } from "komorebi:configuration";
import type { Event, Plugin, ProcessName } from "komorebi:plugin";

type Mode = "normal" | "meeting" | "gaming";
interface ModeState {
  readonly mode: Mode;
  readonly original: AppearanceSnapshot | null;
  readonly ownsChanges: boolean;
}

const meetings = new Set<ProcessName>(["ms-teams.exe", "zoom.exe"]);
const games = new Set<ProcessName>(["eldenring.exe", "hades.exe"]);
let state: ModeState = { mode: "normal", original: null, ownsChanges: false };

function modeFor(event: Event): Mode {
  if (event.type !== "focus-changed" || event.window === null) return "normal";
  if (meetings.has(event.window.processName)) return "meeting";
  if (games.has(event.window.processName)) return "gaming";
  return "normal";
}

async function setAppearance(
  appearance: Pick<AppearanceSnapshot,
    "animationsEnabled" | "bordersEnabled" | "transparencyEnabled">,
  signal: AbortSignal,
): Promise<void> {
  await invoke("set-animation-enabled", {
    enabled: appearance.animationsEnabled,
  }, { signal });
  await invoke("set-border-enabled", {
    enabled: appearance.bordersEnabled,
  }, { signal });
  await invoke("set-transparency-enabled", {
    enabled: appearance.transparencyEnabled,
  }, { signal });
}

async function restoreOriginal(signal: AbortSignal): Promise<void> {
  if (!state.ownsChanges || state.original === null) return;
  await setAppearance(state.original, signal);
  state = { mode: "normal", original: null, ownsChanges: false };
}

const plugin = {
  async onEvent(event, context) {
    if (event.type !== "focus-changed") return;
    const next = modeFor(event);
    if (next === state.mode) return;

    try {
      if (next === "normal") {
        await restoreOriginal(context.signal);
        return;
      }
      const original = state.original ?? await readAppearance({
        signal: context.signal,
      }); // PROPOSED: no configuration snapshot capability exists yet.
      const desired = next === "gaming"
        ? { animationsEnabled: false, bordersEnabled: false,
            transparencyEnabled: false }
        : { animationsEnabled: true, bordersEnabled: true,
            transparencyEnabled: true };
      try {
        await setAppearance(desired, context.signal);
      } catch (error) {
        try {
          await setAppearance(original, context.cleanupSignal);
        } catch (rollbackError) {
          context.log("error", "appearance rollback also failed", {
            error: String(rollbackError),
          });
        }
        throw error;
      }
      state = { mode: next, original, ownsChanges: true };
    } catch (error) {
      if (!context.signal.aborted) {
        context.log("error", "appearance mode transition failed", {
          from: state.mode,
          to: next,
          error: String(error),
        });
      }
    }
  },
  snapshot: () => state,
  restore: restored => { state = restored; },
  async dispose(context) {
    if (context.reason !== "reload-transferred") {
      await restoreOriginal(context.signal);
    }
  },
} satisfies Plugin<ModeState>;

export default plugin;
```

Hot reload must quiesce a plugin: pause delivery, cancel and await its current callback, serialize its snapshot, restore the new runtime, transfer the subscription cursor, mark the old runtime transferred, and only then resume delivery. The disposal context above makes ownership visible and supplies a separate cleanup deadline signal rather than the already-cancelled event signal. The spike proves snapshot/restore into a fresh runtime and complete module-cache invalidation, but its benchmark does not implement this ownership bit, event cursor transfer, or production lifecycle ordering. Normal callbacks must also be serialized per plugin so two focus events cannot race its state.

### Lua/LuaJIT

```lua
-- modes/plugin.lua
local actions = require("komorebi.actions")
local configuration = require("komorebi.configuration")

local meetings = { ["ms-teams.exe"] = true, ["zoom.exe"] = true }
local games = { ["eldenring.exe"] = true, ["hades.exe"] = true }
local plugin = {
  state = { mode = "normal", original = nil, owns_changes = false },
}

local function mode_for(event)
  if event.type ~= "focus-changed" or event.window == nil then return "normal" end
  local process_name = event.window.process_name
  if meetings[process_name] then return "meeting" end
  if games[process_name] then return "gaming" end
  return "normal"
end

local function set_appearance(appearance, context)
  local calls = {
    { "set-animation-enabled", { enabled = appearance.animations_enabled } },
    { "set-border-enabled", { enabled = appearance.borders_enabled } },
    { "set-transparency-enabled", { enabled = appearance.transparency_enabled } },
  }
  for _, call in ipairs(calls) do
    local ok, err = actions.invoke(call[1], call[2], context)
    if not ok then return nil, err end
  end
  return true
end

function plugin:restore_original(context)
  if not self.state.owns_changes or self.state.original == nil then return true end
  local ok, err = set_appearance(self.state.original, context)
  if not ok then return nil, err end
  self.state = { mode = "normal", original = nil, owns_changes = false }
  return true
end

function plugin:on_event(event, context)
  if event.type ~= "focus-changed" then return end
  local next_mode = mode_for(event)
  if next_mode == self.state.mode then return end

  local ok, err
  if next_mode == "normal" then
    ok, err = self:restore_original(context)
  else
    local original = self.state.original
    if original == nil then
      original, err = configuration.read_appearance(context)
      if original == nil then ok = nil end
      -- PROPOSED: no configuration snapshot capability exists yet.
    end
    if err == nil then
      local desired = next_mode == "gaming"
        and { animations_enabled = false, borders_enabled = false,
              transparency_enabled = false }
        or { animations_enabled = true, borders_enabled = true,
             transparency_enabled = true }
      ok, err = set_appearance(desired, context)
      if not ok then
        local rollback_ok, rollback_err = set_appearance(original, context:cleanup())
        if not rollback_ok then
          context:log("error", "appearance rollback also failed", {
            error = tostring(rollback_err),
          })
        end
      end
      if ok then
        self.state = {
          mode = next_mode,
          original = original,
          owns_changes = true,
        }
      end
    end
  end

  if not ok and not context:cancelled() then
    context:log("error", "appearance mode transition failed", {
      from = self.state.mode,
      to = next_mode,
      error = tostring(err),
    })
  end
end

function plugin:snapshot()
  return self.state
end

function plugin:restore(restored)
  self.state = restored
end

function plugin:dispose(context)
  if context.reason ~= "reload-transferred" then
    self:restore_original(context)
  end
end

return plugin
```

Both versions must serialize a fresh copy of state at the host boundary. Production must not retain a Lua table or JavaScript object across runtimes.

## 3. User-extensible focus accent

The current plans do not contain a provider or decoration registration API. This example is therefore an automation behavior, not a pretend `registerDecorationProvider` feature. It uses the real planned `set-border-colour` action whenever focus changes.

Users extend the behavior by adding process-to-colour entries. Because the existing action changes the global colour for a window kind, the accent follows focus globally; it is not a persistent per-window decoration.

### TypeScript/QuickJS

```ts
// accents/config.ts
import type { ProcessName } from "komorebi:plugin";

export type Rgb = readonly [red: number, green: number, blue: number];
export const defaultAccent: Rgb = [66, 165, 245];
export const accents = new Map<ProcessName, Rgb>([
  ["code.exe", [0, 122, 204]],
  ["devenv.exe", [113, 96, 232]],
  ["ms-teams.exe", [98, 100, 167]],
  ["zoom.exe", [45, 140, 255]],
  ["eldenring.exe", [238, 125, 49]],
]);
```

```ts
// accents/plugin.ts
import { invoke } from "komorebi:actions";
import { readAppearance } from "komorebi:configuration";
import type { Plugin } from "komorebi:plugin";
import { accents, defaultAccent, type Rgb } from "./config.ts";

interface AccentState { readonly original: Rgb | null }
let state: AccentState = { original: null };

async function setAccent(rgb: Rgb, signal: AbortSignal): Promise<void> {
  const [red, green, blue] = rgb;
  await invoke("set-border-colour", {
    "window-kind": "single",
    red,
    green,
    blue,
  }, { signal }); // PLANNED: real stable action ID/inputs.
}

const plugin = {
  async onEvent(event, context) {
    if (event.type !== "focus-changed") return;
    try {
      if (state.original === null) {
        const appearance = await readAppearance({ signal: context.signal });
        state = { original: appearance.singleBorderRgb };
      }
      const accent = event.window === null
        ? defaultAccent
        : accents.get(event.window.processName) ?? defaultAccent;
      await setAccent(accent, context.signal);
    } catch (error) {
      if (!context.signal.aborted) {
        context.log("warn", "could not update focus accent", {
          error: String(error),
        });
      }
    }
  },
  snapshot: () => state,
  restore: restored => { state = restored; },
  async dispose(context) {
    if (context.reason !== "reload-transferred" && state.original !== null) {
      await setAccent(state.original, context.signal);
    }
  },
} satisfies Plugin<AccentState>;

export default plugin;
```

### Lua/LuaJIT


```lua
-- accents/plugin.lua
local actions = require("komorebi.actions")
local configuration = require("komorebi.configuration")
local config = require("accents.config")

local plugin = { state = { original = nil } }

local function set_accent(rgb, context)
  return actions.invoke("set-border-colour", {
    ["window-kind"] = "single",
    red = rgb[1],
    green = rgb[2],
    blue = rgb[3],
  }, context) -- PLANNED: real stable action ID/inputs.
end

function plugin:on_event(event, context)
  if event.type ~= "focus-changed" then return end
  if self.state.original == nil then
    local appearance, err = configuration.read_appearance(context)
    if appearance == nil then
      if not context:cancelled() then
        context:log("warn", "could not read original focus accent", {
          error = tostring(err),
        })
      end
      return
    end
    self.state.original = appearance.single_border_rgb
  end

  local accent = config.default
  if event.window ~= nil then
    accent = config.processes[event.window.process_name] or accent
  end
  local ok, err = set_accent(accent, context)
  if not ok and not context:cancelled() then
    context:log("warn", "could not update focus accent", {
      error = tostring(err),
    })
  end
end

function plugin:snapshot()
  return { original = self.state.original }
end

function plugin:restore(restored)
  self.state = restored
end

function plugin:dispose(context)
  if context.reason ~= "reload-transferred" and self.state.original ~= nil then
    set_accent(self.state.original, context)
  end
end

return plugin
```

## Authoring comparison

| Concern | TypeScript + QuickJS/Oxc | Lua + LuaJIT |
|---|---|---|
| First run | Save `.ts`; the host transforms it. No `tsconfig.json`, package install, or bundler. | Save `.lua`; no compile step. A host-defined module resolver is still required. |
| Editor support | Generated `komorebi.d.ts` gives completion, literal action IDs/inputs, discriminated events, lifecycle validation, and refactor-safe config types in ordinary TS editors. | Good completion requires generated LuaLS/EmmyLua annotations and an editor workspace configuration. Misspelled event fields and action arguments otherwise fail at runtime. |
| Modules | Proven confined relative `.ts`/`.mts`/`.js`/`.mjs` ESM and virtual `komorebi:*` modules. Static and dynamic relative imports work. | Idiomatic `require`; the benchmark proves `package.preload`, not the production confined filesystem resolver. |
| Packages | Neither runtime should expose an ambient ecosystem. Permit vendored, plugin-local modules only; no Node/npm resolution, C modules, network imports, or native DLL loading. | Same policy; disable ordinary `package.cpath` and replace unrestricted searchers. Pure-Lua vendoring is possible. |
| Async host calls | Natural `async`/`await`; the spike proves one Tokio-backed promise and top-level await. | Needs host-managed coroutines/yielding functions. The benchmark uses synchronous host calls, so this integration remains unproven. |
| Cancellation | `AbortSignal` is familiar and composable. QuickJS's interrupt hook already proves preemption for CPU-bound script. Native futures still need cooperative cancellation. | A proposed context token handles cooperative broker cancellation. LuaJIT debug hooks or an equivalent owned interruption mechanism still need a production proof. |
| Errors | Generated error classes/unions, source-mapped TS stacks, and exhaustiveness checks. | `nil, error` is idiomatic and explicit, but error shapes and event fields are conventions unless annotations and runtime validators agree. |
| Reload | Fresh runtime, fresh ESM cache, explicit data snapshot/restore is proven in the benchmark. | Fresh Lua state and explicit data snapshot/restore is proven. `package.loaded` is irrelevant when the entire state is replaced. |
| Bundling | Not required. Optional only if profiling later shows a large module graph needs it. | Not required. |
| Runtime cost | About 0.49 ms for the measured two-module TS transform and 1.17 ms median stateful reload. | Roughly 0.13–0.15 ms median stateful reload in measured JIT-off/on modes. |
| Hot execution | Slower in the benchmark, but comfortably below an event-driven automation budget. | Materially faster, particularly for pure script loops. |

### Shown user-authored size

These are physical nonblank lines and UTF-8 bytes inside the example modules above. Generated declarations and explanatory snippets are excluded. The examples are unminified and not code-golfed.

| Scenario | TypeScript | Lua |
|---|---:|---:|
| Workspace routing/layout | 51 lines / 2,038 bytes | 52 lines / 1,821 bytes |
| Meeting/gaming mode | 89 lines / 3,219 bytes | 92 lines / 3,194 bytes |
| Focus accent | 56 lines / 1,975 bytes | 61 lines / 1,852 bytes |

Line count is not the decision by itself. Lua is terser where tables naturally combine data and behavior. TypeScript spends lines on named domain types, then catches wrong process keys, states, event narrowing, tuple sizes, and many host-call mistakes before the plugin starts.

## Configuration and packaging answer

For the recommended TypeScript path, the user experience should be:

1. Create `plugin.ts` and optional relative modules.
2. Import generated capabilities from `komorebi:*` and local files with explicit extensions.
3. Save. The extension worker transforms and evaluates the graph.

There is no user `tsconfig.json`. The host owns a fixed language contract: erasable TypeScript syntax, ESM, a documented ECMAScript target, no decorators or TS features that require semantic emit, and no Node globals. A generated declaration package can be exposed to editors through a host-managed workspace, not copied into every plugin.

There is no required bundler. Direct graph loading preserves file/line diagnostics and makes a two-file automation ordinary. A bundler may be offered later as an optional publishing optimization, never as the edit-run loop or authoritative source format.

Dependency policy should be identical in spirit for both runtimes: capability modules plus confined relative source. Supporting npm resolution would implicitly add package manifests, conditional exports, Node compatibility questions, install scripts, lockfiles, and a much larger sandbox. Supporting native Lua C modules would puncture the runtime boundary even more directly. Useful helpers should be vendored as source or promoted into reviewed host capabilities.

## Design grounding

This comparison was checked against the current implementation worktree rather than extrapolated only from the prototype:

- `docs/implementation/call-stacks/configured-shell-actions.md` assigns catalog binding and authenticated invocation to the plugin adapter and rejects direct protocol or shell construction.
- `docs/implementation/call-stacks/bar-control-actions.md` defines the async command queue and distinguishes coalescible state writes from lossless toggle edges.
- `komorebi-shell/src/action_binding.rs` validates stable IDs and named inputs against the current `CatalogSnapshot` before producing a `BoundAction`.
- `komorebi/src/action/definition/workspace.rs` defines `set-named-workspace-layout`, while `send-container-to-named-workspace` explicitly targets the focused container. That is the evidence for the exact-window routing gap.
- `komorebi/src/action/definition/configuration.rs` defines the automation-permitted appearance actions used here, including the exact named inputs for border colour.
- `komorebi-protocol/src/subscription.rs` and `komorebi-command-transport/src/subscription.rs` provide cursors, topic filters, and an extension subscriber class, but not the typed focus/window payloads shown above.

Those implementation documents are newer than this isolated prototype branch, so they are referenced by path rather than linked as files contained in the branch.

## Product conclusion

LuaJIT wins the measured runtime and reload benchmarks. TypeScript wins the automation authoring comparison because the host can generate one precise contract for event variants, action IDs, named parameters, state, cancellation, and failures, and ordinary editors understand it without extra project files.

That advantage only exists if production implements the typed boundary. Shipping `invoke(id: string, inputs: Record<string, unknown>)` alone would discard much of it. Generate action-specific overloads or a schema map, generate discriminated event types, and keep reload state serializable and versioned.

Before selecting either runtime, close the shared API gaps exposed by these examples:

1. Add an atomic exact-window route action or capability; never emulate it through focus.
2. Define typed event topics and payload versions over the existing bounded subscription lane.
3. Define snapshot/restore/dispose ownership so reload cannot double-clean up.
4. Add a read-only appearance snapshot capability for lossless cleanup.
5. Prove cancellation of both CPU-bound script and in-flight broker calls.

QuickJS still has the separate production gate recorded in `SPIKE.md`: prove the worker under LPAC and resolve the binding/engine maintenance risks. The examples do not weaken that gate.
